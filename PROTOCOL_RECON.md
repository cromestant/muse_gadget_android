# PROTOCOL RECON — Muse Gadgets device protocol (Kotlin port reference)

Read-only recon. SDK at `ref/muse-gadget-sdk` was never built, run, installed, or modified.
Orientation: Linux client is the Home Link counterpart of ESP32 firmware, same pairing + control protocols (ref/muse-gadget-sdk/linux/AGENTS.md:28). ESP32 entry is `main/main.c`, logic in `main/app.c`, UI in `components/muse` (ref/muse-gadget-sdk/esp32/AGENTS.md:26). Linux module map (`cli/pair/pairing/ble_*/identity/muse_api/link_client/service/muse_turn/noise/`) (ref/muse-gadget-sdk/linux/AGENTS.md:30).
C noise crypto core is NOT `esp32/main/noise_*` (session glue) — it is `esp32/components/noise_core/` (`InitiatorHandshake/ClientSession/Transport/ServiceCodec/TransportFrameCodec`). There is no `linux/.../noise/noise_core/` directory and no `noise_xx.*` under `esp32/main/`; the requested `ble_setup.py/ble_framing.py/ble_server.py`, `noise/noise_xx.py`, `identity.py/config.py`, `network.py/link_client.py`, `muse_turn.py`, `muse_adpcm.c/muse_voice.c`, `muse_api.py/muse_chat_text.c`, `muse_link.c/service.py` all exist. There is no `hatch.token` BLE setup command in this revision (only `hatch_refresh:` prefix, `hatch.metaaivm.com`, `hatch-link:*`, `hatch_link` model). There is no `tools/muse/chat.py` at repo root — actual paths are `esp32/tools/muse/chat.py`, `esp32/tools/muse/echo_turn.py`.

### 1.2 Crypto — pairing v5 (NOT Noise tunnel) + Noise XX (VM tunnel)
- Pairing v5 constants: `PAIRING_VERSION=5`, `MODEL=hatch_link`, `SUITE=p256-hkdf-sha256-aes-gcm-v1` (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:45), `POLICY confirm_press/confirm_app`, `AUTH fleet_ecdsa_p256_v1/none` (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:48), `RECORD_LABEL="hatch-link ble setup v1"`, `SESSION_ID_LABEL=b"hatch-link session id v1"` (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:54), timeouts client-finished 60 s / confirmed 120 s / provisioning 120 s / button 60 s (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:57), same labels in C (ref/muse-gadget-sdk/esp32/main/link_pairing.c:50).
- Pairing primitives: P-256 ECDH uncompressed 65 B `0x04||X||Y`, 16 B nonces/session-id, 16 B GCM tag (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:64); HKDF-SHA256 + AES-256-GCM (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:42); `salt=SHA256(mobile_nonce||device_nonce||transcript_hash)`, `session_secret=HKDF(ecdh,salt,RECORD_LABEL)`, `mobile_tx/rx=HKDFExpand(...,"mobile->device"/"device->mobile")`, `session_id=SHA256(SESSION_ID_LABEL||transcript_hash||ecdh)[:16]` (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:170); nonce 12 B `[direction,0,0,0]+counter-BE64`, directions 0/1 (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:72); AAD `"{LABEL}|{session_b64}|m2d|{counter}"` (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:191); counter decimal string, must equal `rx_counter` exactly, failure clears session + disconnect (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:104).
- Transcript canonical `hatch-link-pairing-v5\nversion=5\ninitiator_role=mobile\n…mobile_pub/device_pub/mobile_nonce/device_nonce`, `SHA256`=hash (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:137); community requires `epoch==0`, official `epoch>0`, only `confirm_press` or community+`confirm_app` (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:128); `confirm_timeout 60` if button else 0 (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:152); Linux hello validates `version==5/auth==none/policy==confirm_app` (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:266), ESP32 default `policy==confirm_press` (ref/muse-gadget-sdk/esp32/main/link_pairing.c:723).
- Key-exchange sequence: `pairing_client_hello{version,mobile_pub,mobile_nonce,pairing_auth,pairing_policy}` b64url unpadded (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:278) → `pairing_ready{type,version,device_id,node_id,mac,model,firmware_version,pairing_auth,epoch,policy,device_pub,device_nonce,transcript_hash,session_id[,device_proof]}` (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:325) → `pairing_encrypted{type/session_id,counter,ciphertext,tag}` (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:444) → first decrypted record must be exactly `{"action":"pairing_client_finished"}` with `rx_counter==1` (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:378); Linux `confirm_app` goes `WAIT→READY` directly, ESP32 `WAIT→CONFIRM_REQUIRED→` needs button `confirm_active_session→READY` (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:375); states `IDLE/WAIT_CLIENT_FINISHED/READY/PROVISIONING` + ESP32 extra `CONFIRM_REQUIRED` (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:84); generation tokens bind deferred work (ref/muse-gadget-sdk/linux/src/musegadget/pairing.py:398). `device_info{type,node_id,version,device_id,mac,model,pairing_protocol,auth,epoch,policy,build_sha,network_ready}` (ref/muse-gadget-sdk/linux/src/musegadget/ble_setup.py:194); `provision_v2{ssid,password,access_token,refresh_token,token_type==device}` + optional `username/api_url/api_url_v2/noise_host/ota_url/force` (ref/muse-gadget-sdk/linux/src/musegadget/ble_setup.py:242); community mode only `auth:none/epoch0/policy confirm_app`, online device offers one open network "current connection", ignores Wi-Fi fields (ref/muse-gadget-sdk/linux/AGENTS.md:123).
- Noise XX (VM session, distinct): pattern `Noise_XX_25519_AESGCM_SHA256` both sides (ref/muse-gadget-sdk/linux/src/musegadget/noise/noise_xx.py:30), AES-256-GCM only, no ChaChaPoly (ref/muse-gadget-sdk/linux/src/musegadget/noise/noise_xx.py:27), DHs `ee,es,se` (no `ss`): `ee+es` on msg2, `se` on msg3 (ref/muse-gadget-sdk/linux/src/musegadget/noise/noise_xx.py:459); sequence `->e / <-e,ee,s,es / ->s,se`, wire msg1 32 B `e_pub`, msg2 `e(32)+s_ct(48)+payload_ct`, msg3 `s_ct(48)+payload_ct` (ref/muse-gadget-sdk/linux/src/musegadget/noise/noise_xx.py:33); phases `CREATED→…→SPLIT` (ref/muse-gadget-sdk/linux/src/musegadget/noise/noise_xx.py:398); prologue `h=ck=pad(NAME,32)`, `MixHash("")`, `MixHash(e)` (ref/muse-gadget-sdk/linux/src/musegadget/noise/noise_xx.py:358); payloads empty on Linux (bearer was in WS upgrade) (ref/muse-gadget-sdk/linux/src/musegadget/noise/noise_xx.py:436); nonce `00000000||BE64`, starts 0, `MAX_SAFE 2^53-1`, poison on exhaust (ref/muse-gadget-sdk/linux/src/musegadget/noise/noise_xx.py:251); `MixKey=HKDF(ck,ikm)`, `Split=HKDF(ck,"",2)` (ref/muse-gadget-sdk/linux/src/musegadget/noise/noise_xx.py:368); low-order/all-zero X25519 reject (ref/muse-gadget-sdk/linux/src/musegadget/noise/noise_xx.py:39); ESP32 core same files `InitiatorHandshake.cpp:27` / `CryptoBackend.h:28`.
